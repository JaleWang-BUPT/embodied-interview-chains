卷三 · 数据 · 遥操作 · 真机排障 · 追问链

具身智能面试追问链题库 · 第三卷
题源：牛客 / GitHub / CSDN 一手面经与整理（2025-2026）；可访问来源与调研存证见各链「实录」行
本卷 15 条链 · 57 个问答节点
难度分布：L1 1 · L2 12 · L3 2

使用方式：这卷不要背「先看日志、再逐层排查」这种空话。回答时固定走三步：先保安全与复现现场 → 按时间线/信号链切层 → 给每个假设配一个可证伪的观测。数据题则要把时间戳、坐标系、标签语义说成一条可执行的数据契约。

证据边界：易错项均为编者工程归纳，除明确引用外，不代表原帖候选人曾犯该错误。原题仅由搜索索引保存的链注明索引证据；只有题单而没有外部原文的 C06–C09 全链标推断。

本卷追问模式（来自调研结论）：

  1. 数据怎么来 → 时间怎么对齐 → 标签到底是什么 → 怎么验证：会采不等于能训，时间戳和标签语义错一层，模型会稳定地学错。
  2. 给症状 → 先分层 → 再测量 → 最后改：摔倒、死机、掉压、卡顿都先保留故障现场；没有证据就换参数，通常只会把问题藏起来。
  3. 方案 → 带宽/时延/缓存数字核对：波特率、帧长、中断频率、缓冲区必须能当场估算，不接受「换 DMA 就好了」。
  4. 训练侧 ↔ 执行侧对账：目标指令、实测状态、action chunk、底层实际执行不是同一个量；真机问题常出在它们之间的接口。
  5. 修复 → 如何证明修好了：时间对齐做事件回放，电源问题做空载/带载对比，步态问题做单关节与悬空试验，卡顿问题看端到端时间线。
L2 〔整理〕 C01 · 机器人学习的数据怎么采？采哪些信息？

答：先从训练样本反推采集契约，而不是先开相机。每条 episode 至少记录：任务/成功判据、各相机原始帧与曝光时间、机器人关节位置/速度/力矩或电流、末端位姿、夹爪、力/触觉、操作者输入、下发指令、控制模式、错误码与安全事件。所有流带同一时钟域的单调时间戳、单位、坐标系、设备/标定版本和 episode 边界；原始数据只追加不覆盖，清洗结果另存并可回溯。

追问 1〔整理+推断〕：遥操作、自由度和坐标系具体怎么定？
答：先定 action 接口：关节目标最贴本体，末端增量更易跨操作者但依赖 IK。明确自由度映射、夹爪语义、限位与缩放；每个位姿写 frame id，固定 $T_{world}^{base}$、$T_{base}^{camera}$、$T_{tool}^{tcp}$ 的方向、单位和版本，禁止靠字段名猜坐标系。

追问 2：时间对齐怎么做？
答：硬件触发约束采样时刻，PTP 等方法同步设备时钟，两者不能替代彼此。记录采样和到达时刻，估计设备时钟到统一单调时钟的偏置与漂移；不能用落盘时间代替采样时间。保留原始时间戳、序号和丢帧标志，再按部署可用观测重采样。

追问 3：相机 30 Hz、关节 100 Hz 怎么对齐，为什么必须同步？
答：以决策时刻为锚：图像取当时已到达且曝光不晚于该时刻的帧；状态按部署可用信息选最近值或外推。离线插值可重建真值，但不能把未来才到达的信息当成在线输入。不同步会把状态配上别时刻的动作，产生标签错位；重采样不能跨 episode。

易错：只说「ROS bag 自动带时间戳」——消息到达时间不等于传感器采样时间；不写时钟域、frame、单位和标定版本的数据，录得再多也无法可靠复现。

实录：牛客公开题单（公开前15题含本体/数采/频率；一手身份未独立核实，按整理）+ VLA 面经总结（时间同步与30/100 Hz，整理）；追问1的坐标系细化为推断，不报独立实录频次。

L3 🔥×1 C02 · 相机 30 Hz、状态 100 Hz、控制还有通信延迟，怎样构建时间对齐样本？

答：先定义样本语义。若学习 $\pi(o_t)\to u_t^{cmd}$：以决策时刻 $t$ 为锚，只使用当时已到达的图像/状态，标签用该次决策生成的 $u_t^{cmd}$；另存曝光、到达、生成、发送、接收、执行时间和延迟 $\Delta$。离线状态插值可以重建真值，但不能把未来才可得的信息注入在线输入。预测执行结果时，目标才是 $t+\Delta$ 后的实测状态。按 episode 切分，缺帧/超龄观测显式 mask。

追问 1：怎么验证对齐确实正确？
答：做可观测事件：闪灯/蜂鸣与数字触发同步、夹爪触碰或关节阶跃；把图像事件、命令边沿、电流/编码器响应画在同一时间轴。再算命令与实测速度的互相关估延迟，按设备/时段看残差分布，并回放若干 episode 检查因果顺序。

追问 2：Action 标签是目标指令还是实测状态？
答：默认是策略在该时刻应输出、交给控制器的目标指令，如目标关节角或末端增量；实测状态属于 observation/执行结果。数据格式必须同时写语义、frame、单位、绝对/增量、控制模式与时间戳，不能只叫 action。

追问 3：两者能互换吗？
答：不能直接换。实测状态经过控制器、动力学、饱和、接触和延迟，是目标指令的响应；把它当 action 会改变学习目标。只有明确重建了逆动力学/延迟并验证误差，或任务本来就监督下一状态时，才能构造派生标签，且要与原始命令分字段保存。

易错：为了「对齐」把未来相机帧配给当前动作，离线指标会变好但部署时产生信息泄漏；或把关节实测位置直接命名为 action，训练与控制接口从根上不一致。

实录：offerseed · VLA 算法实习生三轮面经 #6（30/100 Hz + 通信延迟→验证对齐→Action 标签语义，原题顺序）

L2 〔实录·索引记录〕 C03 · 什么样的数据才算「有效」？

答：有效数据应对目标任务有边际训练价值：①标签/时序/标定正确；②包含正样本信号或有用的背景负样本/误检难例；③覆盖部署分布和长尾；④类别/场景/来源不过度偏斜；⑤小规模训练消融能验证收益。保留质量分、拒绝原因和来源，避免只挑清楚、简单、成功的样本。题目的正样本召回目标，不等于通用检测训练都应删除无目标帧。

追问 1：密集检测几十到几百类，怎么做 balance？
答：先按「类别 × 场景 × 尺度 × 遮挡 × 来源」统计实例数与共现。对长尾类定最低配额，用 class-aware/平方根重采样；训练侧配合 focal/class-balanced loss。验证集保持真实分布，并单报 macro、tail AP，不能靠过采样伪造线上分布。

追问 2：1 万张里挑 2000 张有效数据，怎么挑？
答：先剔除损坏/近重复并标记标签异常；用 detector/embedding 产生覆盖与多样性特征。按类/场景分层聚类挑代表样本，保留低置信难例和一定背景负样本；人工复核边界样本。若题目限定挑某类正样本，另报召回，不把筛正样本与构建完整训练集混同。

追问 3：100 万张里只有几万张含目标，只能评估 1 万张，怎么找有效数据？
答：先确认1万张限制是人工标注还是全部评分。若仅限人工，可全量廉价预筛，再对候选分层抽检/主动学习；若连评分也受限，只能用既有元数据分桶、预算内抽样，估计各桶命中率并迭代分配预算。无分布假设时不能保证有限预算找出全部正样本，要报告覆盖与不确定性。

易错：把「有效」等同于高置信、高清、成功轨迹——这样会系统性删掉遮挡、失败恢复和长尾难例，训练集很好看，部署分布却没覆盖。

实录：京东探索研究院原链接（本轮搜索索引保存四问，详情仅外壳；评估预算保留，解释预算语义为独立工程作答，不冒称现场原答）。

L2 〔整理+推断〕 C04 · 真机遥操作和 UMI 各有什么优势、偏差与适用范围？

答〔推断扩展〕：真机遥操作直接得到目标本体上的图像、状态与可执行 action，接触动力学真实、标签离部署接口最近；代价是占机器人、慢、贵，且受操作者抖动、时延和本体能力限制。UMI让人拿便携夹爪/相机在自然环境示范，扩场景快、无需把机器人搬进现场；代价是相机轨迹/夹爪状态要重建并 retarget 到机器人，视角、动力学与可达性有 embodiment gap。选型看任务是否重接触、是否要跨场景扩量，以及 retarget 误差能否接受。

追问 1〔推断〕：什么时候优先用哪种？
答：精密插接、力控、双臂约束与安全敏感任务优先真机遥操；需要大量家庭/长尾场景、机器人难以进入现场时优先 UMI。常见组合是 UMI 做预训练覆盖，少量目标本体遥操做后训练和接口校准，最终以真机闭环成功率裁决。

追问 2〔推断〕：VR/主从臂的最小采集链路怎么搭？
答：操作者设备位姿→统一参考帧→尺度/工作空间映射→IK/约束投影→限速限位与碰撞检查→底层控制；并行记录原始输入、映射后目标、实测状态、多相机与安全事件。先用单臂低速任务跑通延迟、坐标系和急停，再扩双臂/力反馈。

追问 3〔推断〕：怎样从「能遥操」变成「可训练数据集」？
答：版本化标定，定义 episode/成功判据，同步并检查丢帧、限位、碰撞与饱和；人工复核，再按场景/操作者切分。控制初态/环境的安全 replay 可验收接口和时序；接触任务不要求开环动作必然复现，还应看统计闭环结果。

易错：说 UMI「没有本体所以没有偏差」——它只是把真机占用成本换成了位姿估计、retarget、视角和动力学偏差；或只录成功轨迹，不录操作者修正与失败恢复。

实录：VLA 面经总结 只覆盖遥操/示教/VR 优缺点；UMI 对比主问及追问1–3为推断扩展，技术参考 UMI 原论文（不计频）。

L2 〔整理〕 C05 · 怎样获得高质量「思考-行为」数据？

答：先把「思考」定义成可监督、可验证的结构：目标、当前证据、子任务、约束、预期结果与失败恢复；行为则是带时间戳的动作和执行结果。采集时同步第一视角/状态/action，让操作者在关键决策点做短标注或事后基于回放标注，避免边操作边长篇口述改变行为。质量由计划与场景事实一致、动作可执行、结果成功、时间边界对齐、失败原因可信共同决定，不以文字越长越好。

追问 1：LLM 生成这类数据，质量看哪些维度？
答：正确性（物体/状态/约束不幻觉）、可执行性（动作在本体能力与安全边界内）、因果一致性（理由真能支持动作）、时序/粒度一致、覆盖与多样性、重复/污染率，以及训练后的下游增益。自动规则/仿真 verifier、独立模型评审与人工 gold set 要交叉使用。

追问 2〔推断〕：没有大规模金标准，怎么证明评估可靠？
答：先做小而强的分层人工集，双人标注算一致性；在此集上校准 judge 的阈值、偏差与置信区间。再对高分、低分和边界桶分别抽检，监控不同任务/语言/场景的漂移。单个 LLM judge 只能筛选，不能自证正确。

追问 3〔推断〕：生成数据怎样进入训练？
答：生成→规则/执行器验证→去重与难度分桶→人工抽检→按置信度加权；先以小比例混入真实数据做消融，分别看总体、长尾和安全指标。保留 provenance、生成器版本和拒绝原因；若收益只出现在同源 judge 指标、不出现在真机/独立评测，就停止扩量。

易错：用同一个 LLM 生成、打分、再宣布高质量；或把语言上流畅的解释当成物理上正确的决策，完全不做执行/结果验证。

实录：具身智能 VLA 面经总结（「思考-行为」数据与 LLM 生成数据质量两问，〔整理〕）

L2 〔推断·题单待核〕 C06 · 机器人突然摔倒，怎么排查？

答〔推断〕：先急停、断开自主输出并确认人员/机构安全；不要立刻重启覆盖现场。以「最后一个稳定支撑相→首次异常→保护触发」为时间轴分层：①指令/规划是否突变；②状态估计、IMU、接触与时钟是否跳变；③WBC/PID 输出是否饱和、符号/模式是否错；④关节电流/力矩/温度/总线是否异常；⑤电源掉压、线束、机构松动。每层都对比期望与实测，并在吊架/低增益/单关节条件下最小复现。

追问 1〔推断〕：log 怎么采才够定位？
答：用统一单调时钟记录命令、状态估计、原始 IMU/编码器/足力、接触相、控制输出、限幅、驱动器错误、电流/电压/温度、通信序号与丢包；故障前后用环形缓冲保留窗口，事件触发冻结。日志要带软件提交、参数/标定版本和机器人编号。

追问 2〔推断〕：板子和电脑之间怎么传日志？
答：控制面与日志面分离：板端先写无阻塞环形缓冲，低优先级任务经以太网/USB/CAN 分帧发送；每帧带版本、长度、序号、时间戳与 CRC。带宽不足先保关键量并降采样，原始高频数据本地落盘；电脑端按序重组，明确丢帧而不是静默补零。

易错：摔倒后第一反应是「把增益调小再跑」；没有保存首次异常前的原始传感、限幅和错误码，只分析摔倒后的连锁反应。

实录：未找到外部原题；主问与追问全链为推断练习，不能确认题单的公司归属。缺失记录见 卷三题源。

L2 〔推断·题单待核〕 C07 · 板子偶尔死机，怎么设计排查与恢复？

答〔推断〕：先区分「CPU 真停」「任务死锁」「中断风暴」「内存破坏」「外设/总线永久等待」「欠压/时钟复位」。最小侵入地记录 reset cause、关键任务心跳、栈水位、堆水位、HardFault 寄存器、最后状态机和外设超时；用 GPIO/trace 标出关键路径，逐步关闭模块复现。恢复上要有通信/外设超时、局部重启和最终硬件看门狗，但复位不能代替根因定位。

追问 1〔推断〕：看门狗喂狗时间怎么定？
答：超时必须大于正常最坏响应：最长关键任务周期 + 最长合法阻塞（Flash 擦写/通信）+ 调度抖动 + 时钟误差裕量，同时小于系统可接受的失联时间。关键任务各报带序号心跳，由健康监控汇总后喂狗；不要在独立定时中断里无条件喂。

追问 2〔推断〕：复位后怎么知道死前卡在哪里？
答：启动最早期先读 reset-cause；HardFault/看门狗预警或软件监控触发时，最小化保存 PC/LR、SP、当前任务、心跳位图、栈水位和最后若干事件。下次启动先导出再清除。若芯片无预警，就持续把轻量 breadcrumbs 写入 no-init/retention 区。

追问 3〔推断〕：复位后 RAM 数据还在吗，怎么利用？
答：不能一概而论：软/看门狗复位时 SRAM 物理内容可能保留，但启动代码会重拷 .data、清 .bss；掉电则不可靠。需查芯片手册，把故障区放进 retention/backup/no-init section，加 magic、版本、长度和 CRC，验证不同复位源；关键证据仍应落非易失存储。

易错：把狗喂在高优先级中断里，主业务已经死锁仍持续喂狗；或笼统说「复位后 RAM 一定清空/一定保留」，忽略复位源与启动文件。

实录：主问与追问全链缺少可核实原帖，按推断练习；早期补充链接 当前正文未核实，不能证明 PC/LR/retention 层。见 题源记录。

L1 〔推断·题单待核〕 C08 · 一条标称 12 V 的电源线上只读到 5 V，怎么查？

答〔推断〕：先限流、确认量程和同一参考地，核对测点确是 12 V rail 而非稳压后的 5 V。按能量路径分段量：电源空载输出→保险/防反接→连接器/线束→开关管/DC-DC→负载端；同时测每段两端压降。断电测对地阻抗/二极管档找短路或反灌，通电看输入电流与热源，示波器抓启动和纹波。根因常是电源限流/掉压、接触电阻、负载短路、转换器损坏或 5 V 支路反向灌入。

追问 1〔推断〕：空载 12 V、接负载后掉到 5 V，说明什么？
答：优先怀疑过流限流、线束/连接器压降或负载短路，而不是「万用表坏了」。记录电源限流点和负载电流，逐段断开支路并用电子负载替代；哪个支路接入后掉压，就把范围收敛到该支路。

追问 2〔推断〕：能不能直接换更大功率电源试？
答：不能先这么做。若后级短路，更强电源只会扩大损坏。应使用可调限流电源，从低电流缓升并监控温升；确认额定电压、极性、地与保护器件后再替换，且不要绕过保险/限流。

易错：黑表笔接了错误地仍相信读数；或一看到 5 V 就认定 DC-DC 坏了，不做空载/带载、逐段压降和反灌检查。

实录：原 URL 未落盘，主问与追问全链按推断练习，题单不构成外部实录证明；见 卷三题源。

L3 〔推断·题单待核〕 C09 · 上位机和下位机怎么通信？波特率怎么定？

答〔推断〕：先由距离、带宽、节点数、抗干扰和实时性选物理链路（板内 UART/SPI，以太网；多节点强干扰常用 CAN/RS-485）。应用帧至少含 magic、版本、类型、长度、序号、发送时间、payload、CRC。波特率按最坏负载算：$B \ge f\,L_{wire}/\rho$，$f$ 是帧率、$L_{wire}$ 是每帧线上 bit 数、$\rho$ 是允许利用率；再核对时钟误差、线长和收发器能力，不能只报「115200」。

追问 1〔推断〕：丢包怎么办？
答：序号检测丢帧，统计发送/接收/CRC/超时计数并带时间戳定位。先分清发送端没发、物理层损坏、接收 FIFO 溢出还是解析丢弃；连续流用 DMA 环形缓冲和水位告警。控制流通常丢旧保新，配置/升级数据才走确认重传。

追问 2〔推断〕：用什么校验？
答：偶发误码用 CRC（如 CRC-16/32），长度/版本/范围检查抓协议错误；简单和校验只能抓部分错误，不能替代 CRC。CRC 只检测损坏，不检测丢包/乱序，后者靠序号和超时；安全场景还需认证，CRC 不是防篡改。

追问 3〔推断〕：校验失败要重传吗？
答：看数据时效。参数、标定、固件块必须 ACK/NACK + 序号 + 有界重试；高频状态和控制指令重传后往往已过期，应丢弃并等最新帧，连续丢包则进入安全模式。任何重试都要幂等并设上限，防重传风暴。

追问 4〔推断〕：怎样保证实时性？
答：定义端到端 deadline，固定/有界帧长，控制与日志分通道或设优先级；接收用 DMA + 环形缓冲，ISR 只搬数据/唤醒任务，解析在任务中；使用最新值队列，监控队龄而不只看吞吐。对 WCET、总线利用率和拥塞故障做压力测试。

追问 5〔推断〕：中断优先级怎么排？
答：按「错过 deadline 的损失 + 数据不可恢复性」排：安全保护/控制定时器通常最高，易溢出的接收与 DMA 完成其次，日志最低；还要满足 RTOS 可调用 API 的优先级边界。高优先级 ISR 必须短，否则会反过来饿死控制。

追问 6〔推断〕：中断里能不能 printf？为什么慢？
答：生产代码通常不能。格式化尤其浮点会耗 CPU/栈，stdio 可能拿锁且不可重入，串口发送还可能按字节阻塞；115200 8N1 发 100 字节光线上时间就约 8.7 ms。ISR 只写定长二进制事件到无阻塞 buffer，由低优先级任务异步输出。

追问 7〔推断〕：波特率和中断频率怎么算缓冲区？
答：8N1 每字节 10 bit，115200 baud 上限约 11,520 B/s，逐字节中断约 11.5 kHz。若 CPU 最坏 20 ms 不能消费，会积约 230 B；再加一帧 64 B 与裕量，至少取 512 B。还要保证平均输入小于消费速率，否则再大 buffer 也只会晚点溢出。

易错：把 CRC 当成「不会丢包」，控制帧一律重传；或只按平均吞吐选串口和 buffer，不算最坏阻塞时间、线上帧开销与 ISR 频率。

实录：主问与全部追问按推断练习；补充备考文章 是通用建议/专栏推广，不是具体面试实录，不能证明整链或缓存计算层。见 题源记录。

L2 〔实录·索引记录〕 C10 · 机器人步态异常，怎样定位问题来自哪一层？

答：先把症状量化为发生相位、方向、关节、速度与地面条件，再对齐五层期望/实测：①指令与步态相位；②状态估计/IMU/足接触；③规划/WBC 的 CoM、足端与接触力；④关节目标、实测、力矩/电流、饱和/温度；⑤结构松动、线束与电源。做站立→单腿/吊架→低速直行→转向的渐进复现，并交换左右参数/硬件看异常是否随之迁移。

追问 1：关节「软、无力」怎么排查？
答：先看是否进错控制模式、使能/刹车、Kp/Kd/力矩限幅与安全降额；再比期望力矩、下发力矩、电流和实际运动。若命令大但电流上不去，查电压、驱动器、过温/限流和线束；电流大却不出力，查传动打滑、减速器/抱闸；命令本身小则回到控制与标定。

追问 2〔推断〕：怎么判断是标定参数还是运动学参数？
答：编码器零偏常表现为跨姿态近似固定的关节偏置；连杆长度/轴线等运动学误差会随构型系统变化。用独立量具/外部定位采多构型点：先验零位后看 FK 末端残差是否随姿态变化，再做参数敏感性拟合。单纯「软」通常优先查增益、限幅、驱动与机构，不要先改 DH/URDF。

易错：上来就重新标定或调 PID，不先判断异常跟着关节、相位、方向还是地面走；同时改多个参数，最后无法归因。

实录：测试业务面经原链接（搜索索引含步态/关节软/标定；详情正文本轮未取回，不声称当前全文可读）。

L2 〔实录+整理〕 C11 · VLA 真机停滞、动作不连贯或卡顿，怎样定位瓶颈？

答：先做端到端 trace，而不是只测 model.forward()：$t_{capture}$、传输/解码、预处理、排队、GPU 推理、后处理、发布、控制器接收和实际执行都打同一时钟时间戳，同时记录 queue depth、chunk age 与 deadline miss。用 p50/p95/p99 区分稳定慢、抖动和周期性阻塞；若吞吐够但队列增长，是背压/旧帧堆积，不是单纯算力不足。

追问 1〔推断〕：确认推理延迟高后怎么处理？
答：先消除同步拷贝与重复编码，做预处理/推理/执行异步流水和预分配；再用 FP16/BF16、编译/算子融合、视觉 token/分辨率裁剪或小模型。控制端用 action chunk 覆盖推理间隔并设超时 hold/安全停；优化要同时看延迟分位数与真机成功率。

追问 2：推理期间机器人已运动，新 chunk 从哪里执行？
答：不能从第0步硬接。朴素异步执行应跳过已过期动作；RTC 还在推理时固定/约束旧 chunk 中延迟窗口内已承诺执行的前缀，在新观测下补全后续动作以保持相容。普通状态重规划和重叠预测平均并不等于 RTC；超龄结果按安全规则处理。

追问 3：怎么区分模型预测、chunk 拼接和底层控制问题？
答：三次隔离：离线画模型原始 chunk 看边界是否跳；固定 chunk 用软件执行器回放看拼接；把最终目标送仿真/空载底层看跟踪误差。原始就跳是模型/数据，原始连续而合成后跳是拼接，目标连续但实测停顿则查控制频率、限幅、通信与 watchdog。

易错：只报平均推理耗时；或通过增大 chunk 掩盖停顿，却不处理旧观测、队列堆积和 chunk 边界，动作会更流畅但更陈旧。

实录：offerseed #6（推理/控制频率不一致、chunk 交界停顿与归因原题）+ 具身智能 VLA 面经总结（真机卡顿/延迟，〔整理〕）

L2 🔥×1 C12 · 遥操作过程中，人走动的问题怎么解决？

答〔场景展开为推断〕：先确认需求：操作者只是调整站位，还是希望机器人跟随移动？若是前者导致手臂/基座误动，先分清操作者参考系变化与机器人定位漂移。建立 operator anchor，手臂用躯干相对目标；以 clutch/recenter 解耦换位与控制，重锚时保证指令连续。若需要全身跟随，再用死区、缩放和限速映射显式 locomotion 指令，机器人在自身 odom/map frame 闭环跟踪。

追问 1〔推断〕：怎样快速判断漂移来自哪一侧？
答：同时画人体参考位姿、base command、机器人 odom，并用外部固定参照、轮速/IMU确认机器人是否真实运动。零命令而 odom 变，可能是定位漂移，也可能是外力/惯性/残余目标。冻结映射/定位的 A/B 先在离线回放或仿真中做，避免直接破坏真机闭环。

追问 2〔推断〕：移动底盘和双臂怎样保持一致？
答：在 map/odom 中规划底盘，在实时 base frame 表达双臂相对目标；每周期用最新 $T_{map}^{base}$ 变换，不把旧基座位姿烘进手臂目标。基座重定位/跳变时冻结或平滑手臂目标，并检查全身 IK、可达域与碰撞约束。

易错：把所有人的平移都当成底盘增量连续积分；或只给信号加低通，漂移速度变慢了，但坐标系和重锚错误仍在积累。

实录：Cgxiaoxin 原始面试复盘（湃特纳二面：人走动问题；原文未限定为基座漂移，答案与两层排查为推断）；技术参考 Humanoid Teleoperation Survey（不计频）

L2 〔实录主题+推断〕 C13 · 全部示范都一次成功，模型就一定好吗？如何从数采减少累计误差？

答：一次成功率 100% 的演示集是偏乐观分布：缺失败与恢复覆盖，闭环遇到扰动没有先验；操作者漂移也会被完整学习。减少累计误差从数采侧入手：任务分解与阶段重置点（允许中途复位重示范）、记录失败并附恢复段、操作者指令平滑、按初态/物体/扰动做多样性覆盖，而不是只堆同质成功。

追问 1〔推断〕：抽帧对训练和部署有什么问题？
答〔推断·工程作答〕：抽帧丢快瞬态、时间间隔不均；训练侧动作-观测时间结构被破坏，部署侧观测频率与训练不一致会放大滞后与抖动。按固定节拍采并保留原始时间戳，比事后均匀抽帧稳。

追问 2〔推断〕：任务里哪个阶段最容易出错？为什么可能是"铺平"这类子任务？
答〔推断·工程作答〕：柔性/接触密集子任务（铺平、插入、理线）状态部分可观测、形变难逆、误差跨阶段累积，失败率通常最高。按阶段统计失败率定位短板，而不是全任务均匀优化。

易错：用演示成功率预测部署成功率——分布覆盖比"好看的成功率"更决定闭环表现。

实录：卷三题源 C13。题面为维护者提供场次原题，作答与展开为推断。

L2 〔实录主题+推断〕 C14 · 主从位姿不齐，为何只偶尔抖动而非每次？

答：抖动"偶尔"出现说明有触发条件：①主从标定误差在工作空间大部分区域被控制器吸收，靠近奇异位形或边界时被放大；②传动间隙/摩擦只在换向时显性化；③丢包或插值节拍错位只在特定时序组合出现；④操作者指令在死区附近往复。排查用复现法：记录抖动时刻的位形、速度方向与通信日志，找共性条件。

追问 1〔推断〕：怎么系统性消除？
答〔推断·工程作答〕：全空间标定并验证误差分布、换向区死区补偿或摩擦前馈、指令平滑限幅、通信时间戳对齐；逐项消融确认主因再投入。

追问 2〔推断〕："不是每次都抖"能排除标定问题吗？
答〔推断·工程作答〕：不能——标定误差本来就是位形/方向相关的，"偶尔触发"恰恰常是它的证据；用全空间网格测误差分布再下结论。

易错：凭"偶尔抖"直接排除标定——位形相关误差正是偶尔触发的典型来源。

实录：卷三题源 C14。题面为维护者提供场次原题，作答与展开为推断。

L2 〔实录主题+推断〕 C15 · 原始数据如何做降采样滤波？

答：先定目标频率（控制/训练节拍）再看信号带宽：降采样前必须抗混叠低通（截止 < 新奈奎斯特频率），否则高频噪声折叠成假信号。滤波选择：离线用 Butterworth + 零相位 filtfilt；在线因果回路用滑动均值/中值（去尖刺），并把相位滞后计入稳定裕度。图像/状态/力各通道分别定参，滤波器参数写进数据契约，训练与部署保持一致。

追问 1〔推断〕：在线回路和离线数据集的做法有何不同？
答〔推断·工程作答〕：在线只能因果滤波（有延迟代价），离线可用零相位；两条管线滤波不一致会造成训练-部署分布差。

追问 2〔推断〕：降采样丢的信息怎么评估？
答〔推断·工程作答〕：对比降采样前后的重构误差/高频能量与下游任务指标；接触瞬间等关键快变量优先保采样率。

易错：先降采样后滤波（顺序反了必然混叠）；所有通道共用一个截止频率。

实录：卷三题源 C15。题面为维护者提供场次原题，作答与展开为推断。
